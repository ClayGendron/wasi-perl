## Findings, ranked

### High: the specification cannot be built as written

**H1. 022 and 021 add new kinds of line to `MANIFEST`. wasi-perl's `MANIFEST` cannot hold them.**
- 022:173 has `make_package_snapshot(None)` read `x-snapshot-package` lines from the set's `MANIFEST`. 021:47 and 021:58 have `MANIFEST` record binaryen's version and hash.
- wasi-perl's `MANIFEST` is strictly `<sha256>  <path>`, one line per file under `lib/` and `dev/`. `scripts/30_library.sh:62-68` writes it. `tests/build/test_modules.py:529-550` asserts that every line holds a 64-hex digest and that the entries are exactly the files on disk (READ). wasi-python's `MANIFEST` has another format.
- Neither spec decides the new format, who writes it, or how the runner and that test read it. Changing that test without a decision would weaken a check.
- **Fix:** decide this in 022 and point 021 to it. One option is a separate file (for example `PACKAGES`), pinned by `SHA256SUMS`. The other is a stated `MANIFEST` format change, with the writer, the reader and the changed test named, and with how it maps to wasi-python's lines.

**H2. 019, 021 and 022 each add a build step, and no specification decides their order. As written, the order is impossible.**
- 022:8 puts the reactor's link in `scripts/20_target.sh`. 022:14 and 022:96 say the reactor links 019's index. 019:92-93 generates that index in `scripts/30_library.sh`, which runs after `20_target.sh`.
- 019 does not say which script holds its relink, or which stamp covers it. 021:35 refers to "the relink step of spec 019" as if it existed.
- `30_library.sh:70-72` hashes `perl.wasm` into `SHA256SUMS`. A relink or `wasm-opt` after that leaves `SHA256SUMS` stale.
- The first link needs an index symbol. Nothing says it gets an empty index object.
- **Fix:** write one pipeline in 019, and have 021 and 022 cite it:
  1. the target link, with an empty index;
  2. `installperl` and the library;
  3. the index source;
  4. the relink of `perl.wasm` and the link of `perl-reactor.wasm`;
  5. `wasm-opt` over both;
  6. `MANIFEST` and `SHA256SUMS`.

  Name the script and the stamp for each step.

**H3. 019's index answer changes the errno of the library escape checks.**
- 019:97 says "a path not in the index answers `ENOENT` with no host call", for `path_open` too.
- `tests/escapes/test_escapes.py:365` (`lib-new`: `open ">", "/usr/local/lib/perl5/x"`) expects `PERM` at :376. `:386` (`create-in-lib`) expects `PERM` at :394 (READ). Under 019 both would answer "No such file or directory". 019:103-111 claims the answers are unchanged.
- A second case: a path below an indexed file, such as `5.42/strict.pm/x`, gets `ENOENT` from the index where the host answers `ENOTDIR`.
- **Fix:** the index answers only lookups that cannot create: `path_filestat_get`, and a `path_open` with no `O_CREAT`, no `O_TRUNC` and no write rights. Any other open goes to the host and keeps its `EPERM`. A path below an indexed file answers `ENOTDIR`. Add both cases to 019's check 3.

**H4. 021's feature flags leave out features `perl.wasm` uses.**
- 021:52 lists exception handling, bulk memory, sign extension, non-trapping float-to-int and mutable globals, and says "No others are enabled".
- Study B's `wasm-opt --print-features` on base also shows `--enable-reference-types`, `--enable-multivalue`, `--enable-extended-const`, `--enable-bulk-memory-opt` and `--enable-call-indirect-overlong` (`perf-codegen/results/static.txt:11-21`, EXECUTED there). `try_table` and `exnref` need reference types.
- Study B passed no feature flag (`results/wasm-opt-repeat.txt:1`), so wasm-opt read the module's `target_features` section.
- **Fix:** pass no feature flags, as study B did. Add a check that `--print-features` gives the same list before and after the pass.
