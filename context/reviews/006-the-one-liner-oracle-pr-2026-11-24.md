## Corpus review

- **Reflects agents:** yes, for the most part. `-ne`, `-pi`/`-pi.bak`/`-iorig_*`, `-lane`, `-F,`, `-F'\t'`, `-0777`, `-00`, `-0`, `$.` and `eof` across files, `close ARGV`, `ARGVOUT`, script files with `#!` switches, and the warnings and `die` texts are what coding agents actually type. A few cases are synthetic load (`num-fib`, `count-large-sort`, `text-big-regex`). They are cheap, deterministic and worth keeping. The real gaps are paths (M4) and the environment (L3).
- **Hash order:** every printed hash goes through `sort keys` or a fully ordered comparator. Ties are broken: `count-by-frequency` and `count-word-frequency` use `|| $a cmp $b`. `scalar(%h)` is a count in 5.42. `Data::Dumper` uses `Sortkeys` and `JSON::PP` uses `canonical`. The sweep above confirms all of this.
- **Flakiness:** I found nothing time-, pid- or random-dependent. `err-die-mid-stream` exits with a stale `ENOTTY` from perl's start-up probe. That is stable because both sides always run with stdout on a pipe, and the spec records it.
- **Native outputs read for intent:** I listed every case with a non-zero exit, a non-empty stderr or an empty stdout. Each is the intended outcome (for example, the `-i` cases print nothing and change files, and `.bak`/`orig_*`/`.orig` backups appear in the snapshot). No case "matches" only because both sides fail in the same unintended way. READ.

## Path normalisation

`normalise` (`oneliner_oracle.py:195-214`) touches only native results. It is applied once, inside `run_native`, so live and recorded results are treated the same. It replaces the work directory's given and `realpath` spellings, longest first, by `/work`. Guest output is never rewritten, so a guest that leaked a host path would show as a difference. Normalisation could hide a path-length dependence such as `length(cwd)`. The determinism test's second, longer directory catches that: the two normalised runs would then disagree. I see no way for it to hide a real difference with today's corpus. The leak check (`test_oneliners.py:74-77`) runs after normalisation, so it effectively catches the install prefix and paths above the work directory. That is what decision 8 asks for.
