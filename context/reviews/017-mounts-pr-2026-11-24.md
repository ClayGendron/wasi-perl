**H2. The placeholder clean-up follows a symlink the guest made, and removes a folder outside every grant.**
- Evidence (EXECUTED: `placeholder_symlink.py`). The guest has a writable grant over the temporary folder, the case E4's third run allows. It renames its call's `wasi-perl-*` folder away. It makes a symlink of the same name to `../victim`; wasmtime accepted the relative target. After `run` returns, `victim/mount`, an empty folder outside every grant, is gone: `victim/mount still there: False`. `_remove_placeholder` calls `os.rmdir("<tmp>/wasi-perl-*/mount")`, and the host follows the symlink in the middle component (READ: `runner.py:411-425`).
- The damage is narrow: it removes only an empty folder named `mount`, wherever the host user can write. But the host acted outside the sandbox at the guest's direction. Decision 5 says the clean-up "never deletes what the guest put there"; here it deletes what the guest did not put there.
- Creation has the same window (INFERRED): `mkdtemp`, then `os.mkdir(folder/mount)` and `os.chmod`, all by path. A concurrent call's guest that holds a writable grant over the temporary folder could swap `folder` between those steps.
- The check does not hold the rule either. Mutating `os.rmdir(path)` to `shutil.rmtree(path)` passes all 194 mount and mount-escape checks (EXECUTED: `mutants.txt`, `placeholder-rmtree`). The guest's replacement is a file, so a tree removal fails on it just as an `rmdir` does.
- **Fix:** hold the folder by descriptor. Open it with `O_DIRECTORY | O_NOFOLLOW` right after `mkdtemp`, keep its `(st_dev, st_ino)`, and make, chmod and `rmdir` `mount` with `dir_fd=`. Remove the folder itself only while `lstat` still gives that identity. Alternatively, put the placeholder under a folder no grant may reach, as wasi-python does (`_call.py:492-497`), with a grant rule that refuses it. Extend E4's third run in two ways:
  - put a folder of the same name, holding a file and a `mount` subfolder that holds a file, so a tree removal would show;
  - add the symlink case, asserting that the outside empty folder survives.

## What holds

**The sandbox at the table.** I read every handler path a guest can drive. All of these are wasi-python's code at `f9bf678`, unchanged apart from the trims (READ). I also mutated the key lines; the results are in "The order breach" below.
- **Paths.** `_resolve` refuses these with no provider call:
  - an absolute path (`EPERM`);
  - a NUL, `\` or `:` (`EINVAL`);
  - a component over 255 bytes, or a path over 4,096 (`ENAMETOOLONG`);
  - a `..` above the descriptor's folder (`EPERM`);
  - any path at or under a more specific preopen: the library, `/dev`, a grant or a mount (`EPERM`).
- **Links.** A provider cannot report a link: `Stat.kind` and listed kinds are `file` or `dir`, and anything else is a fault.
- **Guest memory.** Every pointer and length is masked to 32 bits and checked by `_Memory.fits` against the memory's size before a read or a write. Misaligned pointers and out-of-range flags end the run as wasmtime's ABI does. I found no way for a guest to make the host read or write outside its memory.
- **The fault boundary.** It is `except Exception` around each provider call and each answer's judgement. A `BaseException` stops the call and is raised from `run` after the store is closed, with no write-back. A coroutine answer is closed.
- **Limits.**
  - The deadline and the file-call limit are checked before every provider call (`_gate`).
  - Staging is bounded at `memory_bytes`.
  - `MAX_MOUNT_FILES` stands behind the guest's own 256-number table.
  - A blocking provider is outside the deadline in both runtimes, and the docs say so.

**No reach into the module cache or the runtime files.** A mount has no host folder, so `judge` takes only its guest path, for `cwd`. A mount-only call computes no rule input (A6). Every path into `/usr/local/lib/perl5` or `/dev` spelled through a mount above them is `EPERM` (D6, E5). The provider never sees a library path (READ, EXECUTED by the checks).
