# wasi-perl 0.1.0: security and structural review, 2026-11-24

- **Reviewer:** an agent (Claude), a fresh sub-agent; wrote none of wasi-perl.
- **Reviewed:** `origin/dev` at `7afccfb` (001 to 006 and 003's amendment), in a detached worktree. Also read: `origin/spec/008-ci` (`178b8c5`), `origin/spec/009-fd-table` (`f5199bd`), and the local branch `spec/010-special-files-and-select` (`54e312c`; it is not on origin).
- **Artifacts used:** `/home/user/wasi-perl-wt/002-xs/build/artifacts` (perl.wasm `49c687b9…`), and for the 009/010 claims `/home/user/wasi-perl-wt/009-fd/build/artifacts` (perl.wasm `b9f93537…`, built from the 010 branch).
- **Host:** Linux x86-64, uid 0, umask 022, wasmtime-py 51.0.0, Python 3.13. Running as root hides permission-based checks, so I did not test anything that depends on them.
- **Compared with:** wasi-python's 0.1.0 to 0.1.6 security reviews (H1 cache planting, F4 the cache's descriptor, GHSA-f2pq-268w-886c, the 0.1.6 L1 version floor) and the structural rubric in `context/reviews/README.md`.
- **Labels:** EXECUTED (I ran it; the probe scripts are in `scratchpad/probes/`), READ (code or document), INFERRED (reasoned, not run).

## What held (EXECUTED unless marked)

- `uv run pytest tests/escapes tests/runner` gave 171 passed, 1 skipped and 1 xfailed (the FIFO). `uv run pytest -m "not slow"` gave 2 failed, 176 passed and 210 skipped. The 2 failures are the `from conftest import` clash, which 008 fixes. `ruff check` is clean.
- **A read-only grant stays unwritten.** I tried `link`, `rename` out of it, `truncate` by name and by handle, `utime`, `unlink`, `mkdir`, a `+<` open and `chmod`. Each was refused and the file did not change (`probes/link.py`).
- **No read escapes a grant.** I tried `..` climbs, `/./..`, a climb through `/usr/local/lib/perl5` and through `/dev`, `//etc`, host-made relative and absolute links, a mixed `sub/../../` link, and a link the guest made to a link. Each was refused.
- **No host environment variable reaches the guest.** The guest's `%ENV` is exactly `env=`, `$^X` is `perl`, and `/` is not listed. A planted `SECRET_TOKEN` did not appear. `--env KEY` passes a value only on purpose.
- **Code planted in a reused writable grant** (wasi-python's H2 class): Perl loads nothing from the working folder ('.' is not in `@INC`). `site_perl` sits inside the read-only library (READ, INFERRED). `PERL5OPT` and `PERL5LIB` arrive only through the embedder's own `env=`.
- **The cache's own checks hold** (READ). It reads through the checked descriptor, so wasi-python's F4 is already closed here. It checks the way to the folder with `_way`. It refuses a file with a second name. The default folder, `$WASI_PERL_CACHE` and this call's `cache_dir` are all kept out of every grant.
- **Output stays within its cap.** A single 17 to 64 MiB `syswrite` keeps exactly 16 MiB and names `stdout` in `truncated`. A 400 MiB write fails inside the guest with ENOMEM.

| M1 | Medium | `src/wasi_perl/runner.py:192-213` (`_runtime_folders`), `_grants.py:283-289` | **Hard links defeat "a writable grant may not reach wasmtime or the set".** The rule compares folders, not files. uv, the project's own tool, installs by hard link by default on Linux and Windows. So every file of wasmtime-py and of the wheel has a second name in uv's cache (nlink is 21 here). A writable grant of a folder that holds uv's cache, but neither the venv nor the wasi_perl cache, passes the judge. The guest can then rewrite `_libwasmtime.so`, which the next host process loads as native code. The same route rewrites `lib/perl5/*.pm`: the tree is re-hashed only once per process, so later calls in the same process run the changed modules (INFERRED). A new process refuses the set, which is fail-closed. | EXECUTED (`probes/hardlink.py`): a scratch venv with `UV_CACHE_DIR=work/uvcache`, then `Grant(work/uvcache, "/c", writable=True)`. The guest appended `GUEST-WAS-HERE` through `/c/archive-v0/…/_libwasmtime.so`, and the venv's `_libwasmtime.so` grew 14 bytes with that tail. | Once per process, `lstat` the runtime's own files: wasmtime's shared library and `.py` files, wasi_perl's, perl.wasm, MANIFEST and the lib tree, the last when it is hashed. If any has `st_nlink > 1`, refuse every writable grant, with a message to reinstall with `--link-mode=copy` (or `UV_LINK_MODE=copy`). Say so in README "Not protected" and in the install line. |
| M2 | Medium | `src/wasi_perl/_cache.py:110-115` (`every`), `:126-144` (`_as_made`); `_grants.py:276-282` | **A guest can plant a `.cwasm` that a later call loads as native code.** The cache rule covers only the caches this call can name. A folder granted writable earlier, or by a concurrent call, and named as `cache_dir` (or `$WASI_PERL_CACHE`) later is not tracked. The file name is public: the digest from SHA256SUMS, the wasmtime version and the flavour. On POSIX the planted file passes the mode check under umask 077, or when the guest renames a host-made 0600 file such as one from `mkstemp`. On Windows no mode is checked at all. This is wasi-python's 0.1.0 H1 in a narrower form. | EXECUTED (`probes/cache.py`, umask 077). Call 1 had `cache_dir=False` and a writable `Grant(D, "/w")`. The guest wrote real `.cwasm` bytes from stdin to `/w/cache/<digest32>-wasmtime51.0.0-plain.cwasm` (mode 0600, folder 0700). Call 2 had `cache_dir=D/cache`, and `_engines.counts()` went from `loaded 0` to `loaded 1`. | Keep a process-lifetime set of the identity chains of every writable grant. Refuse (warn and compile in the process) a cache folder at or under any of them, and add the cache folders in use to the live registry so that a concurrent writable grant above one is refused. Document the cross-process case: never point `cache_dir` at a folder a guest has written. |
| M3 | Medium | `runner.py:326-330` (preopen outside any `try`); the guest has no descriptor cap on dev; `FD_LIMIT 1024` in the 009/010 table | **One guest exhausts the host process's descriptors, and a concurrent `run()` then raises.** On dev each guest open is a host descriptor with no cap. 009/010 caps a call at about 1,020, which is still at or above Linux's default soft limit of 1,024 and four times macOS's 256. A concurrent call's `preopen_dir` then raises `wasmtime.WasmtimeError("failed to add preopen dir")`, a type `run()` does not document. The embedder's own sockets and files fail in the same window. | EXECUTED (`probes/fds.py`, `fds2.py`). On dev with `ulimit -n 20000` the guest held 19,988 descriptors (host peak 19,999). With `ulimit -n 1024`, three concurrent `run()` calls each raised `WasmtimeError: failed to add preopen dir`. Consider raising `RLIMIT_NOFILE`'s soft limit toward the hard limit once per process. |
| L1 | Low | `cli.py:502-507`; `runner.py:340` | **Ctrl-C does not stop a running guest.** SIGINT is handled only once the wasmtime call returns. With `--deadline-s none`, or with H1's sleep, the command ignores Ctrl-C until it is killed. | EXECUTED: with `wasi-perl run --deadline-s 8 -- -e '1 while 1'`, SIGINT at 2 s exited 130 at about 8 s. | Run the call on a worker thread. Verdict on structure: it holds once R4 (one process object) and R5 (one platform module) are reserved as specifications. Neither blocks the release.

## Release verdict

**Not ready: H1 (a guest `sleep` holds `run()` past every limit) and H2 (007, 008, 009 and 010 unmerged, so there is no wheel, no CI, no CHANGELOG and a red fast suite on `dev`).** M1 to M3 should be fixed or documented in "Not protected" before the tag. The Lows can ride with the release.
