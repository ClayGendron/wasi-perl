## The problem

perl.wasm is a WebAssembly command. A host must start it with exceptions turned on, preopen the library read-only at `/usr/local/lib/perl5` and the artifact `dev/` at `/dev`, give it exactly the folders the caller grants, bound its memory, time and output, compile it (about a second for a module this size, INFERRED from wasi-python) only once per machine, and say how it ended. Every embedder would write that, and each would get some of the safety wrong. The package `wasi_perl` does it once, as `run()` and as `wasi-perl run`, the same as wasi-python does for CPython.

## Decisions

1. **The public API** is `wasi_perl.__all__`: `run`, `Grant`, `Completed`, `Defaults`, `defaults`, `set_defaults`, `artifacts`, `Artifacts`, `ArtifactsMissing`, and `__version__ = "0.1.0"`; plus the `wasi-perl` command, `python -m wasi_perl`, and the environment variables `WASI_PERL_ARTIFACTS` and `WASI_PERL_CACHE`. Everything else is internal. `import wasi_perl` does not import wasmtime-py; `run` does, and if it cannot load, `run` raises `ImportError` naming `wasmtime>=51,<52`, with wasmtime-py's own error as the cause.

2. **`run`.**
   ```
   run(argv, *, grants=(), env=None, stdin=None, cwd=None, fuel=None,
       deadline_s=<60.0>, memory_bytes=<1 GiB>, output_bytes=<16 MiB>,
       cache_dir=None, artifacts=None) -> Completed
   ```
   - `argv` is the guest's arguments after `perl`: `["-ne", "print if /x/", "/data/f"]`. The guest's `argv[0]` is `perl`. An empty `argv` runs the program on standard input, as `perl` does.
   - `Completed(exit_code, stdout, stderr, trapped, fuel_used, truncated)`, frozen, as wasi-python's first six fields mean:
     - `exit_code`: the guest's exit status (`exit N`, `die` uncaught is Perl's own 255, a normal end is 0); `None` when it trapped.
     - `stdout`, `stderr`: bytes, each up to `output_bytes`.
     - `trapped`: `None`, or `"out of fuel"`, `"deadline"`, or wasmtime's words: a trap's code as plain words (`"stack overflow"`, `"unreachable"`), else the first line of wasmtime's error (an instantiation refused for memory, say). The two fixed strings are promised; wasmtime's words are not.
     - `fuel_used`: with `fuel`, the instructions spent (`fuel` itself when it ran out); `None` without `fuel`, or when the deadline ended the call (the count is stale then).
     - `truncated`: a tuple naming each stream (`"stdout"`, `"stderr"`) that passed `output_bytes`, in that order.
   - **Nothing the guest does makes `run` raise.** A trap, an exit, a deadline, a write refused: each is in `Completed`. `run` raises only for its caller's mistakes and the host's state, before the guest runs: `TypeError`, `ValueError`, `ArtifactsMissing`, `ImportError`, `OSError`.

3. **Every argument is checked before any work** (wasi-python specs 013, 014, 017; `TypeError` for a wrong type, `ValueError` for a bad value; a message names the argument, and for a grant its position, never an environment value):
   - `argv`: an iterable of `str` but not a `str` itself; no NUL; valid UTF-8 (no lone surrogate).
   - `env`: a mapping of `str` to `str`, or `None`; keys non-empty, without `=` or NUL; values without NUL; both valid UTF-8. `PWD` is refused: the working folder is `cwd`'s (Decision 5).
   - `stdin`: bytes-like or `None` (empty).
   - `fuel`, `memory_bytes`, `output_bytes`: an `int` (not `bool`) from 0 to 2**63 − 1, or `None`. `deadline_s`: a real number (not `bool`), finite and above 0, or `None`.
   - `grants`: an iterable of `Grant`, not a `str`. Each grant's own checks are Decision 4's. `cwd`: Decision 5's. `cache_dir`: Decision 8's. `artifacts`: an `Artifacts` or `None`.

4. **Grants.** `Grant(host, guest, writable=False)`, a frozen dataclass; `host` a `str` or `os.PathLike[str]`, `guest` a `str`, `writable` a real `bool` (`"no"` is a `TypeError`, not truthy).
   - **The guest path** is absolute, normalized (no empty, `.` or `..` component, no trailing `/`, no `\`), not `/`, and is neither at, under nor above `/usr/local/lib/perl5` or `/dev`: those two are the runtime's, and a grant above one (`/usr`) would put a folder the caller controls on the way to the library. No two grants share a guest path; nested guest paths are allowed (wasi-libc picks the longest prefix).
   - **The host path** must exist and be a directory. It is resolved once, link by link, from the absolute path: a symbolic link on the way is followed only if the folder that holds it is one this user cannot write (so `/tmp -> /private/tmp` on macOS is followed, a link a guest could have made in a writable grant is not); on Windows every link or junction on the way is refused. The resolved path is what wasmtime opens.
   - **Read-only is read-only.** A read-only grant is `preopen_dir(host, guest, fs_mutable=False)`: every write-type call through it (create, write, truncate, unlink, rename, mkdir, rmdir, symlink, link, chmod-like `fd_filestat_set_*`) answers `EPERM`. A read-only grant whose host folder is, or is inside, a writable grant's is refused, since the guest could change it through the other.
   - **The runtime's files are out of reach.** No grant, read-only or writable, is at or inside the module cache in use or any other cache this user's processes could use (`$WASI_PERL_CACHE`'s and the platform default's), so the guest never reads or plants a `.cwasm`; and no writable grant is at, inside or above the artifact folder, the library folder, the `dev/` folder, the module cache's folders, this package's own folder or wasmtime-py's, since a guest that rewrote any of them would change what the next call or the next host process runs. Comparisons are by `(st_dev, st_ino)` of the folders and their ancestors, never by spelling, so a case-changed spelling on macOS is still caught. A folder that does not exist yet (the cache on a fresh machine) is judged by its deepest existing ancestor.
   - **Always granted, read-only:** the library folder, `<artifacts>/lib/perl5`, at `/usr/local/lib/perl5` (so `@INC`'s `/usr/local/lib/perl5/5.42` and its `site_perl` kin are found), and `<artifacts>/dev` at `/dev` (spec 001, `test_dev_null`). They are preopened first, then the grants in the caller's order.
   - **Nothing is writable by default.** With no grant the guest sees only those two read-only folders: there is no `/`, no `/tmp`, no `HOME`; `open(my $f, ">", "x")` fails. A writable grant is the one way to write.
   - What is not done here, and why: wasi-python's post-preopen identity check (a WAT module reading the `ino` wasmtime opened, against the walk's descriptor) is left out of this first package: it closes a race in which a folder on the way is swapped between the check and wasmtime's own open, which needs another writer of the host's folders at that instant, and the guest is not one (a guest's own writes start after the open). It is listed in the README's "Not protected" and is a candidate for a later specification.

5. **The working folder.** `cwd` is `None` or a guest path, normalized as a grant's, that is a grant's guest path or lies under one; the host folder it names (the grant's resolved host plus the rest) must exist, be a directory and stay inside that grant once resolved by Decision 4's link rule. The runner then sets `PWD=<cwd>` in the guest's environment. perl.wasm moves there at start-up: a constructor in the build (spec 001's recipes) calls `chdir(getenv("PWD"))` before `main`, through wasi-libc's own `chdir`, which keeps the working folder inside libc. Without `cwd`, `PWD` is unset and wasi-libc's working folder is `/`, which no preopen serves, so a relative path fails with `ENOENT` (or `ENOTCAPABLE`), as with no root in wasi-python. Until spec 001's build carries the constructor, a perl.wasm without it ignores `cwd` and relative paths fail; the checks of `cwd` that run real Perl skip on such a build, saying why.

6. **The environment** is exactly the caller's `env` plus `PWD` from `cwd`: nothing of the host's environment, no `HOME`, no `TMPDIR`, no `PATH`. `PERL5OPT`, `PERL5LIB`, `PERLLIB`, `PERL5DB` and Perl's other variables are passed as given, and the runner adds none. They only make the guest load or run guest-side code from paths the guest can already read (the verified library, or a grant the caller gave): code the guest's own program could load with `require` or run with `eval`. The wall is WASI, not the interpreter's options, so refusing them would protect nothing and would break callers who use them on purpose (`PERL5LIB=/lib` over a read-only grant of modules). What could change the next call is a file planted in a folder that a later call reads code from; the grant rules keep the library, `/dev` and the cache out of every writable grant, and what a caller re-grants writable between calls is the caller's own.

7. **The limits** have the defaults wasi-python has, in a frozen `Defaults(memory_bytes=1 << 30, deadline_s=60.0, output_bytes=16 << 20)`, checked by `run`'s own rules at construction. `defaults()` returns the one in force; `set_defaults(new)` swaps it under a lock and returns the old one. `run` reads it once, when called. "Not given" is a private sentinel, so `None` keeps meaning "no limit".
   - **Deadline** by epoch interruption, which costs nothing per instruction: every engine has `epoch_interruption = True`; a call sets `store.set_epoch_deadline(ceil(deadline_s / 0.01))`, or 2**62 ticks for no deadline (a store with epochs on and no deadline set would trap at once). While at least one call with a deadline runs, one ticker thread per process advances every engine's epoch once per 10 ms of elapsed monotonic time, catching up after a long sleep (wasi-python's `_epoch_ticker`, adapted). A deadline ends the call with `trapped == "deadline"`. A guest blocked in a host call (none here can block: stdin is bytes, output is a callback) is not interrupted until it returns.
   - **Fuel** by a second engine with `consume_fuel = True`, since metering changes the compiled code; a call with `fuel` uses it. The store runs instantiation with a huge budget (wasmtime may charge for its own memory fill where it cannot map the image) and sets `fuel` just before `_start`.
   - **Memory** by `store.set_limits(memory_size=memory_bytes)`: `memory.grow` past it returns −1, so Perl's `malloc` fails and Perl says "Out of memory!" and exits; an initial memory above the cap fails instantiation, reported as `trapped` with wasmtime's first line.
   - **Output** per stream, by `WasiConfig.stdout_custom` and `stderr_custom` callbacks: each keeps bytes until the stream holds `output_bytes`, drops the rest, still returns the full length (so the guest's write succeeds and does not retry), and marks the stream truncated. No temporary file is written, so a guest that writes without end uses no disk and at most `output_bytes` of memory per stream, until its deadline or fuel ends it. Temp files (`stdout_file`) were rejected: their size is bounded only by the deadline, which is disk use the caller never asked for. wasi-python moved to pipes for speed (wasmtime hands a callback 4 KiB at a time, with a Python thread state each time); the callback is the simple, portable form, and speed is a later memo's question.
   - **Stdin** is given to wasmtime as bytes through the C API's `wasi_config_set_stdin_bytes` (called through wasmtime-py's own `_ffi`, the one private name this package uses), so no file holds it either.
   - The guest runs on the calling thread, with wasmtime's default wasm stack (512 KiB of native stack for wasm frames; Perl's C stack is the 8 MiB in linear memory). The store is closed in a `finally`, trap or not.

8. **The module cache** (wasi-python's `_engines._module`, `_load`, `_store` and the POSIX and Windows checks of `_platform_*`, adapted and trimmed).
   - **Where:** `cache_dir` is a path (made absolute when the call is made; `""` is refused), `None` or `True` (then `$WASI_PERL_CACHE` when set and not empty, else the platform default: `$XDG_CACHE_HOME/wasi_perl` or `~/.cache/wasi_perl` on Linux and other POSIX, `~/Library/Caches/wasi_perl` on macOS, `%LOCALAPPDATA%\wasi_perl\cache` on Windows; none when there is no home), or `False`: no cache on disk, modules kept in this process only.
   - **Key:** `<first 32 hex of perl.wasm's SHA-256>-wasmtime<version>-<plain|fuel>.cwasm`: the binary's bytes, wasmtime-py's version (a `.cwasm` is native code for one wasmtime), and the flavor (metering changes the code).
   - **Compiled from bytes hashed once.** perl.wasm is read once into memory; for a found set its SHA-256 must equal the one checked against `SHA256SUMS` (else `ArtifactsMissing`); the module is compiled from those bytes, so a `.cwasm` is never written under a digest its source does not have. Within a process, modules are kept per `(flavor, digest)` and compiled once even under concurrent calls.
   - **The folder, on POSIX:** made at 0700 if missing; it must be a directory owned by this user with no group or other bits, checked by `lstat` and again through its open descriptor; and every folder on the way to it, links resolved, must be this user's or root's and not writable by group or other unless sticky (as `/tmp` is). Otherwise it is not used, with a `RuntimeWarning`, and the module is compiled in the process.
   - **A `.cwasm`, on POSIX:** opened inside the checked folder's descriptor with `O_NOFOLLOW`; it must be a regular file with one name (a hard link is a file elsewhere), owned by this user, mode 0600 (no group or other bits); its `fstat` stamp (device, inode, size, mtime) must equal its `lstat` stamp taken before the open. It is then read through that same descriptor and given to `Module.deserialize`, so what was checked is what is loaded. A file that fails a check, or that wasmtime refuses (stale, another version, corrupt), is replaced by the runner's own; a folder at its name is never replaced.
   - **On Windows:** no mode bits and no owner comparison; the folder must be a directory and the file a regular file with one name, neither a link nor a junction (reparse point), checked by `lstat` and by the open descriptor, and the file is read through the descriptor that was checked. The grant rule (Decision 4) is the guard that keeps a guest from the cache.
   - **Writing:** `mkstemp` in the folder (0600), the serialized module written, `os.replace` onto the name, which replaces a refused file or link itself, never what a link names. A cache that cannot take it warns and the call goes on.

9. **The artifact set.**
   - **Found** as `$WASI_PERL_ARTIFACTS` when set and not empty; else, when this package runs from a source checkout of wasi-perl (`<repo>/src/wasi_perl/` with `<repo>/pyproject.toml` naming `wasi-perl`), its `build/artifacts/` when that holds `perl.wasm`; else the wheel's own `src/wasi_perl/artifacts/` when it holds `perl.wasm`. Otherwise `ArtifactsMissing`, whose message says how to get one.
   - **`Artifacts(perl, lib, dev, manifest, sums)`**, frozen: `perl.wasm`, `lib/perl5` (granted at `/usr/local/lib/perl5`), `dev`, `MANIFEST`, `SHA256SUMS`. `artifacts()` returns the found set's paths without checking it.
   - **Checked before use.** `SHA256SUMS` is `sha256sum`'s own format (`<hex>  <path>` per line, paths relative to the set, `/`-separated), listing every file of the set but itself: `perl.wasm`, `MANIFEST`, every file under `lib/` and `dev/null`. A found set's `perl.wasm` and `MANIFEST` are hashed and compared on every call, the digest kept per file stamp (device, inode, size, mtime, ctime) so an unchanged file is not hashed again. The library and `dev/` are a tree of a few thousand small files, so they are checked once per process per stamp of `SHA256SUMS`: every listed file under `lib/` and `dev/` must hash as listed, and every file present under them must be listed, since an unlisted `.pm` is code Perl would load. `dev/` must hold exactly the one empty file `null`. A mismatch is `ArtifactsMissing` naming the file. A set the caller passes as `artifacts=` is the caller's own and is used as given, as in wasi-python.
   - The writer of `SHA256SUMS` is the build's (spec 001's assembly step, and spec 008's release); `scripts/write_sums.py` in this specification writes it for a set in the format above, so the build calls one tool.

10. **The command line** (wasi-python specs 019 and 022, followed).
    - `wasi-perl run [OPTIONS] [--] ARG...` and `python -m wasi_perl run ...`. The guest's argv is split off by wasi-python's one left-to-right scan: everything after the first `--`; or, without `--`, from the first argument that is not an option (an option that takes a value consumes the next argument unless written `--name=value`). `argparse` with `allow_abbrev=False`.
    - **Options, each one `run()` argument:** `--grant GUEST=HOST` (read-only) and `--grant-writable GUEST=HOST`, repeatable, into one list in the order typed, split at the first `=` (so `C:\data`, UNC paths and host paths holding `=` pass whole; a value with no `=` is a usage error naming the option); `--cwd GUEST`; `--env KEY=VALUE` or `--env KEY` (this command's own value, so a secret stays off the command line; a missing `KEY` is a usage error that never echoes it); `--stdin PATH` or `--stdin -`; `--deadline-s`, `--memory-bytes`, `--output-bytes`, `--fuel` (each takes `none` for no limit); `--cache-dir PATH` or `--no-cache` (`cache_dir=False`). An option not given is not passed, so `run()`'s default applies.
    - **Output:** one JSON line on standard output, `json.dumps(..., sort_keys=True, ensure_ascii=True)` plus `\n`, written as ASCII bytes and flushed: `exit_code`, `fuel_used`, `trapped`, `truncated` (a list), and `stdout` when its bytes are valid UTF-8, else `stdout_base64` (standard base64), and the same for `stderr`. This is wasi-python's choice: text is what agents read, base64 keeps binary output exact; output cut inside a character comes as base64.
    - **Exit codes say whether there is a result:** 0, the call returned (the JSON says how the program ended); 1, `run()` raised, or `--stdin PATH` could not be read, with one JSON line `{"error": ..., "kind": ...}`; 2, a usage error (argparse's message on standard error, nothing on standard output); 130, Ctrl-C.

11. **The package.** `pyproject.toml`: hatchling, the version read from `src/wasi_perl/__init__.py`, `dependencies = ["wasmtime>=51,<52"]`, `[project.scripts] wasi-perl = "wasi_perl.cli:main"`, wheel packages `src/wasi_perl` with `src/wasi_perl/artifacts` named as wheel `artifacts` (it is git-ignored, and hatchling honours that unless it is named); description "A secure Perl 5 sandbox for agent-generated code, compiled to WebAssembly as one static binary."; licence Apache-2.0; readme `README.md`; dev group `pytest`, `ruff`; ruff line length 100, rules E, F, I, UP, B, TID252. Modules adapted from wasi-python say so in their docstrings.
