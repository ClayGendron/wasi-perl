# Changelog

## Unreleased

### Added

- Preload images the embedder makes: `make_package_snapshot()` loads `strict`, `warnings`, `POSIX`, `List::Util`, `JSON::PP`, `Data::Dumper`, `Storable` and `Encode` once, and a call given `run(..., snapshot=snap)` starts with them compiled. On one Linux VM, `use strict; use warnings; use POSIX; use JSON::PP; use List::Util` takes about 5 ms instead of 23 ms, and 18 M guest instructions instead of 120 M; a bare `-e 1` takes about 0.7 ms more, so pass the image only to calls that load modules. `make_snapshot(code)` keeps what any code left. The API is wasi-python's: `Snapshot` (with `save`, `load` and `check`), `SnapshotOrigin`, `SnapshotFailed`, `SnapshotMismatch`, `make_snapshot`, `make_package_snapshot`, `run(snapshot=)` and `Completed.image_sha256`; the differences are listed in specification 022 and each says how wasi-python could adopt it. wasi-perl ships no image: each making draws its own hash seed from the host's randomness, which every call from that image shares, so `docs/snapshots.md` says to keep the image, its saved file (written at 0600) and the module cache as private as a key, and to make an image only from your own code. On Linux each call maps the image copy-on-write; on macOS and Windows it is written into each call's memory. A call whose `env` names `PERL_HASH_SEED`, `PERL_PERTURB_KEYS` or `PERL_JSON_PP_USE_B` runs `perl.wasm`. Specification 022; the numbers are in `context/research/2026-11-24-the-preload-image-measured.md`.
- A new artifact, `perl-reactor.wasm`: the same Perl linked a second time as a WASI reactor, with `recipes/wasi-reactor.c` in place of `perlmain.o`, after the same `wasm-opt -O3` pass. A preload image starts from it; it holds no image and no seed. `SHA256SUMS` pins it, the wheel carries it (3.2 MB more, 13.3 MB in all) and it is a release file. `Artifacts` gains `reactor`, an optional last field, so a set made by hand with five paths still runs every call but those from an image. `MANIFEST` is unchanged. `perl.wasm` is unchanged in behaviour. `wasi-perl run --no-snapshot` is accepted, as wasi-python's command line takes it, and changes nothing.
- Mounts: `run(argv, mounts=[Mount(provider, "/work")])` serves the guest's files from the embedder's own code, read-only unless `writable=True`. The API, the provider protocol, the limits and the record are wasi-python's, name for name: `Mount`, `FileProvider`, `WritableFileProvider`, `Errno`, `Stat`, `FileFault`, `RefusedWrite`, `FileRecord`, `run(max_file_calls=)`, `Defaults.file_calls` (10,000) and `Completed.files`. The code is adapted from wasi-python at f9bf678, trimmed only of what wasi-perl does not have. `cwd` may lie in a mount. A mount writes no host file and adds no import; a call without mounts is unchanged. `perl.wasm` is unchanged. Specification 017; `docs/mounts.md` says what each Perl operation costs a provider, and `context/research/2026-11-24-mounts-beside-wasi-python.md` lists every difference from wasi-python.
- `docs/fast-perl.md`, the fast way to write common programs in the sandbox, with each number a ratio of guest instructions: `-0777` for whole-file regex work (9× fewer for a count of matches, 7.5× for `-pi -e 's///g'`), a Schwartzian transform instead of `split` inside a `sort` block (5×), `JSON::MaybeXS` or `Cpanel::JSON::XS` instead of JSON::PP (29× on decode), `Text::CSV` instead of Text::ParseWords (13×), `use POSIX ()` instead of a bare `use POSIX` (whose 587 names cost 16 M instructions on every run). It also says that `File::Find` needs a `cwd` to give the right answer: without one it dies "Can't cd to /" or finds nothing. Linked from the README and `docs/modules.md`. Every example on the page is a one-liner case compared byte for byte with native perl, and every number is a fuel check within 20%. The one-liner cases that use the CPAN modules form their own group: native perl runs them with `build/native-cpan` on `PERL5LIB`, an oracle without the five pinned versions there fails them rather than skipping, and a recorded oracle carries the versions, so one made with others is stale (its format is now 2). CI counts the page's guest checks in its skip gate. Specification 020; the numbers are in `context/research/2026-11-24-fast-perl-measured.md`.
- JSON, CSV and diff modules from CPAN. Cpanel::JSON::XS 4.83 and Text::CSV_XS 1.65 are linked into `perl.wasm`; JSON::MaybeXS 1.004008, Text::CSV 2.06 and Algorithm::Diff 1.201 are in the library. Each is built from a CPAN tarball pinned by URL and SHA-256 in `downloads/SHA256SUMS`, with no change to its source; all five are under Perl's own terms. Decoding a 1.4 MB JSON file takes 370 M guest instructions instead of JSON::PP's 11,156 M (45 ms instead of 1,250 ms on one Linux VM), and parsing 50,000 quoted CSV rows 1,511 M instead of Text::ParseWords' 18,215 M. `use JSON::MaybeXS` picks Cpanel::JSON::XS, and `use Text::CSV` picks Text::CSV_XS. `perl.wasm` grows by 126,212 bytes and imports nothing new. One output differs from JSON::PP: a float with a whole value encodes as `5.0`, not `5`. `docs/modules.md` lists the five. The build refuses a tarball that is unpinned, off its pin by one byte, or not one top folder, before it touches its build tree. Native perl gets the same five in `build/native-cpan`, apart from the oracle's library. Specification 018; the numbers are in `context/research/2026-11-24-json-csv-and-diff-measured.md`.

### Security

- Perl's seeds now come from the host's randomness. Before, the guest had no `/dev/urandom`, so Perl seeded its hash order, its internal random state and `srand` from the time of day, which can be guessed from when a call started; that weakened Perl's defence against hash flooding. Now the guest serves `/dev/urandom` and `/dev/random` itself, from WASI's `random_get`, which `perl.wasm` now imports; the host never sees the name. The device answers as Linux's does. An open with no access mode, as Perl's seed makes, now reads as on Linux, so `sysopen(F, $path, 0)` opens a handle for input where it failed with EINVAL. `docs/sandbox.md` lists what differs from native.

### Changed

- `perl.wasm` is now binaryen's `wasm-opt -O3` output, run once after the last link. The guest runs 2.0–3.4% fewer instructions on every workload measured, so a fuel budget does that much more work, and the module is 8.1% smaller (9,443,860 → 8,675,094 bytes). binaryen `version_133` is a new pinned build input, by URL and SHA-256 in `downloads/SHA256SUMS`; it runs only as a build tool. `scripts/40_link.sh` names the module's eleven features as flags and stops if wasm-opt reads others in the module. The pass is deterministic: the build's checks run it again and get the shipped bytes. The module no longer carries a name section, so a trap's backtrace names functions by number; the runner's errors, which keep only the cause, are unchanged. wasm-ld's output stays in `build/link/perl.wasm` for comparison. With it, the five-module program of 019 runs 1.25% fewer instructions than before the library index. Specification 021; the numbers are in `context/research/2026-11-24-wasm-opt-measured.md`.
- Loading modules asks the host only about library files that may exist. `perl.wasm` now holds an index of its library's 1,728 files and folders. For a path under `/usr/local/lib/perl5` that no host could find, the guest answers "no such file" itself: ENOENT, or ENOTDIR below a file. Every other lookup is still the host's, among them a name in another case, which macOS and Windows find, a name Windows rewrites or cannot hold, and a path the host refuses as too long or not UTF-8. So `use strict; use warnings; use POSIX; use JSON::PP; use List::Util` makes 0 failed host stats instead of 118, and `-MPOSIX -e 1` 0 instead of 73. On one Linux VM the five-module program takes 23.8 ms instead of 27.9 ms, for 1.2% more guest instructions. `@INC`, `.pmc` handling and every error a program sees are unchanged; a write-shaped open of the library still gets the host's EPERM. A set's `perl.wasm` serves only the library it was built with: a file added to a set's library, even one passed with `run(artifacts=...)`, is not found. The library must be mounted read-only, as the runner mounts it. To add Perl code, grant it in its own folder and name that with `-I` or `PERL5LIB`; `docs/modules.md` says so. The build links `perl.wasm` a second time, after the library, in a new step, `scripts/40_link.sh`, which also writes `SHA256SUMS`; `build/artifacts/` now holds only shipped bytes. Specification 019; the numbers are in `context/research/2026-11-24-the-library-index-measured.md`.
- A call with a writable grant costs 2.7 ms instead of 22.3 ms, and a fresh process's first call 73 ms instead of 104 ms, its library check 46 ms instead of 79 ms, on one Linux VM (medians). On Linux and macOS the runtime's files are scanned once per process, and the scan is used again while every folder it walked keeps its stamp; a folder changed within two seconds of a scan is scanned again. The writable grants are still walked on every call, so the hard-link rule refuses what it refused before. The library check walks its tree with string paths, and every new process still hashes every library file: a kept record of hashed files was refused, since a write through a shared mapping can change a file without moving its stamp. Specification 015; the timings are in `context/research/2026-11-24-the-runners-fixed-cost-measured.md` §8.
- The guest makes far fewer host calls on files, and less work per line. PerlIO reads and writes a file 64 KiB at a time instead of 8 KiB, so a 10 MB log takes 157 `fd_read` calls instead of 1,248. `memchr`, which Perl calls for each line it reads, is our own and compares sixteen bytes a step with SIMD128 instead of four: 11% fewer guest instructions on a grep over a log, 20% on counting its lines. The descriptor table answers `isatty` itself for a regular file it looked at before opening it, which spares one host call per file opened. On one Linux VM, a grep over a 10 MB log takes 61 ms instead of 114, `-pi` over it 122 ms instead of 202, and a grep over 200 small files 45 ms instead of 58. So `perl.wasm` now needs a host with SIMD128, which wasmtime enables by default; `docs/sandbox.md` says so. Perl's behaviour does not change. Specification 016; the numbers are in `context/research/2026-11-24-the-guests-reads-and-writes-measured.md`.
- A call's fixed cost on the host is smaller: a bare warm call 3.9–4.5 ms → 1.4–1.8 ms, and a fresh process's first call about 135 ms → 114 ms, with 36 MiB less peak memory, on one Linux VM. wasmtime-py's version is read once per process, from its dist-info; `SHA256SUMS` is parsed once per stamp of the file; a rule's inputs are found only when a grant can break the rule; each compiled module is linked once; on Linux the checked `.cwasm` is copied into a sealed memory file that wasmtime maps, instead of being read into Python and copied again, so nothing done to the cache's file afterwards reaches the running module; and the engine states the four wasmtime defaults the speed depends on. Every rule is unchanged. Specification 014; the timings are in `context/research/2026-11-24-the-runners-fixed-cost-measured.md`.

## 0.1.0 — 2026-11-24

The first release. One pinned set: Perl 5.42.3, built with wasi-sdk 34 for `wasm32-wasip1`, run with wasmtime 51.

### The runtime

- `perl.wasm`: Perl 5.42.3 as one static WebAssembly module. It imports only `wasi_snapshot_preview1` and needs a host with exception handling (`die` and `eval` unwind through WebAssembly exceptions, not Asyncify). It is built from pinned sources with a hand-written `config.sh`, a host miniperl and no patch to Perl.
- The core XS modules are linked in statically, among them POSIX, List::Util, Scalar::Util, Data::Dumper, Storable, Encode and its tables, Digest::MD5, Digest::SHA, MIME::Base64, Time::HiRes, Cwd, File::Glob, IO, Fcntl, Socket, Compress::Raw::Zlib and ::Bzip2, Unicode::Normalize, Unicode::Collate, Time::Piece, B and Opcode. JSON::PP, File::Spec and the rest of the pure-Perl core library ship as one read-only folder. `docs/modules.md` lists what is left out and why: threads, IPC::SysV, Sys::Syslog, the DB_File family and PerlIO::mmap.
- Processes and signals are refused, clearly. `fork`, `exec`, `system`, backticks, pipe opens, `pipe`, `wait`, `waitpid`, `kill`, `alarm`, `dump` and a `%SIG` handler each die with "… is not available in the wasi-perl sandbox", which `eval` can catch. `$SIG{__WARN__}` and `$SIG{__DIE__}` work. Core modules that set a handler while they load, such as Math::Complex, still load.
- Exit statuses match native Perl on Linux. An uncaught `die` exits 255. An exit taken from `$!` uses Linux's errno numbers. Statuses are masked to 0–255. wasmtime 51 refuses statuses of 126 and above, so the module exports `wasi_perl_exit_status` for the host to read them.
- Descriptors behave as on POSIX. The guest's own table gives `dup`, `dup2`, `F_DUPFD`, `>&STDOUT` and the `&=` forms, numbered lowest-free, so Test::More works. Four-argument `select` reads Perl's bit vectors.
- In-place editing works on every host, Windows included: when the host refuses to rename over a file the guest holds open, the guest releases its own handles on it and retries.
- Special files are refused at open (`ENXIO`), so a FIFO in a grant cannot hold the host. Every clock wait is cut into 10 ms slices, so a sleeping guest keeps its deadline.

### The Python package

- `run(argv, *, grants=[Grant(host, guest, writable=False)], env, stdin, cwd, fuel, deadline_s, memory_bytes, output_bytes, cache_dir, artifacts)` returns `Completed(exit_code, stdout, stderr, trapped, fuel_used, truncated)`. `wasi-perl run [OPTIONS] -- ARG...` prints the same as one JSON line.
- Safe by default. No host folder, no network and nothing writable unless granted. Every call has a deadline (60 s), a memory cap (1 GiB) and an output cap per stream (16 MiB). The guest's environment is only what the caller passes.
- Grants are checked before any work. Guest paths are normalised. A grant may not overlap the runtime's own library, a module cache, this package, wasmtime or the host Python's folders. Within one process, a call's grants may not overlap another live call's writable grants.
- The compiled module is cached as wasi-python caches it. The folder must be 0700 and owned by the user, files are 0600, and a module is loaded through the descriptor that was checked and compiled from bytes hashed once. A folder any call of the process granted writable is never used as a cache.
- The artifact set is checked against its `SHA256SUMS` before use.

### Judged by

- Perl's own `t/` suite, run one file per guest: 616 files, 439 pass and 0 fail; the other 177 are listed in `tests/perl_t/exclusions.toml`, each with its reason (143 start a child process, 11 need signals, 2 are refused calls, 6 check Perl's own source tree, 6 are WASI differences, 6 are for other systems, 3 are known bugs), a failure signature and a floor of passing results that may not fall (19,052 in all).
- 209 agent-style one-liners (`-ne`, `-pi -e`, `-lane`, `-F`, `-0777`, `-00`, modules, errors, Unicode, paths), byte for byte against native perl 5.42.3, on Linux x86-64 and arm64, macOS arm64 and Windows x86-64. Two cases differ on a Windows host, each allowed with its reason: NTFS gives a directory a size of 0, and writing to a directory there fails with EINVAL, not EISDIR.
- wasi-python's sandbox escape tests, ported to Perl: reads outside a grant, `../` and absolute climbs, links made by the host or the guest, every kind of write to a read-only grant, FIFOs, a guest that sleeps forever, and planted code.
